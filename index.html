Pre-billing invoice validation — POC

Workday holds the draft customer invoices; POMS is the commercial truth they must agree with. Five legal entities (DE21, SE21, NO21, PT21, DK21), every invoice line with a Sales Item and a Revenue Category, and seeded scenarios for each entity exception — normal cases, passing cases and failing cases. All customers, contacts and addresses are fictional. The dataset is served as static JSON so an external validation agent can read both systems.

Layout variant 5 — text noise and ARIA grids: labels carry trailing colons, mixed case and icons; every Workday grid is a role="grid" of divs; the worklist filter placeholder, the worktag chips and both not-found messages differ; the invoice page holds a hidden print copy of every field. Same data, same routes, same answer key as bv-poc.

System under validation

Workday — Customer Invoices

Find Customer Invoices worklist with company and PASS / FAIL / HOLD filters; View Customer Invoice with Invoice Lines (Sales Item, Revenue Category, description, quantity, unit price, extended amount), Tax, Validation and Related systems tabs. Flagged cells are highlighted.

 Source of truth

POMS — Order Management

Vehicle orders with buyer, financing partner, VIN, licence plate, base price, fees, gross taxable amount, VAT and total. Each order links to the Workday invoices raised against it and their latest validation result.

Reading it from Python

import requests

BASE = "https://<you>.github.io/<repo>"
invoices = requests.get(f"{BASE}/api/workday/customer-invoices.json").json()["data"]
orders   = {o["order_number"]: o for o in requests.get(f"{BASE}/api/poms/orders.json").json()["data"]}

for h in invoices:
    inv   = requests.get(f"{BASE}/api/workday/customer-invoices/{h['invoice_number']}.json").json()["data"]
    order = orders.get(inv["poms_order_number"])
    for line in inv["lines"]:
        print(inv["invoice_number"], line["line"], line["sales_item"], line["revenue_category"], line["extended_amount"])
