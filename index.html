Pre-billing invoice validation — POC

Workday holds the draft customer invoices; POMS is the commercial truth they must agree with. Five legal entities (DE21, SE21, NO21, PT21, DK21), every invoice line with a Sales Item and a Revenue Category, and seeded scenarios for each entity exception — normal cases, passing cases and failing cases. A rule engine validates the whole dataset every hour and publishes the result back here.

System under validation

Workday — Customer Invoices

Find Customer Invoices worklist with company and PASS / FAIL / HOLD filters; View Customer Invoice with Invoice Lines (Sales Item, Revenue Category, description, quantity, unit price, extended amount), Tax, Validation and Related systems tabs. Flagged cells are highlighted.

 Source of truth

POMS — Order Management

Vehicle orders with buyer, financing partner, VIN, licence plate, base price, fees, gross taxable amount, VAT and total. Each order links to the Workday invoices raised against it and their latest validation result.

 Hourly scheduler

Validation monitor

Latest run, run history, hits per rule, results per invoice against the POC answer key, and POMS orders that were never invoiced. Fed by validator/validate.py — locally via scheduler.py or on GitHub via the hourly Actions cron.

Run the validator

# against this hosted copy
python3 validator/validate.py --base-url https://<you>.github.io/<repo> --check

# against the local checkout, then keep going every hour
python3 validator/validate.py --check
python3 validator/scheduler.py

# rebuild the dataset after editing a generator
python3 build.py
